核对日期：2026-11-14。本机微信缓存版本 76 的协议包与主包用于离线核验。解包文件只保留在被忽略的 `work/` 下，不随仓库分发。

## 实际协议与客户端规则

- `GuildCityArmyPop._onBtnFinishGuildOrder` 发送 `FinishGuildOrderRequest({cityId})`，回执为 `FinishGuildOrderResponse.reward`。截图的「募兵」与项目的「联盟订单」是同一个协议动作，不是英雄招募接口。
- `GuildOrderNumCfg` 按当前赛季及不高于玩家等级的最高档决定上限；`maxNum=-1` 表示游戏未限制，0 表示当前档不可提交。每日已完成次数来自完整 `CounterInfoResponse.counters` 中的 `DAILY_FINISH_GUILD_ORDER`。
- `GuildOrderRequest` 返回 `order.requirements` 与 `nextRefreshTime`。`GuildCityInfoRequest` 返回本联盟城市与推荐标记，使用已确认的推荐城市，无推荐时选择已确认的本盟城市。
- `GuildUtil.isGuildHelpItem` 只允许 `GuildHelpCfg` 中、`season <= 当前赛季` 的材料；`getMaxAidNum()` 读取 `GuildParamCfg` 的「每日求助次数上限」（当前配置为 20）。
- 普通联盟援助为 `AidType.AID_GUILD = 0`。发布 `GuildAidAskRequest({reqItemId,type:0})`，帮助 `GuildAidHelpRequest({reqId:[精确int64],type:0})`，每个请求消耗一件材料。不能与活动食材互助的类型混用。
- 我的援助查询为 `MyGuildAidRequest({type:0})`，`GotMyGuildAidRequest({type:0})` 一次领取当前全部已获援助，不支持按单条 ID 领取。只有核对原记录消失才确认领取；库存净增减不是唯一依据。
- 领取福利使用已有 `GotGuildWelfarePackRequest/Response`，同时核验回执领取时间和奖励。
- 科技使用 `GuildTechInfoRequest`、`SeasonTaskStageRequest`、`UpgradeGuildTechRequest({techId})`；回执 `tech.techId` 和 `level` 必须匹配下一等级。仍区分普通科技点与职级科技点。

## 一致性与资源保护

- `alliance.enabled` 接管时，同类旧联盟订单、赠送和领取任务应避让，不同时执行。
- 帮助次数使用已有 `guildAidGifts` 持久计数，手动与自动共用；求助以服务器 `DAILY_GUILD_AID` 计数为准，不为不同模式另开额度。
- 自定义赠送须满足允许材料、禁止材料、昵称任一子串（忽略大小写）、库存保留量，并保留周订单、贸易港和居民订单材料。贡献模式赠送固定本赛季材料，不读取隐藏的自定义允许名单，但仍遵守可见的禁止赠送材料和昵称筛选。每日末补齐也遵守对应模式的全部规则。
- 主动求助与赠送材料名单独立：允许／禁止赠送不会阻止自己请求材料；请求只取主动求助名单、当前缺料或贡献模式固定材料，并遵守游戏赛季可用清单。
- 不指定求助材料时，只从已确认订单预留不足的材料，以及尚未达到每日上限的当前募兵缺料中选择；指定材料时允许在没有缺料的情况下求助。募兵自动求助不依赖募兵补产开关。
- 发送前持久占用用量与唯一记录；超时、断线或不完整回执保留记录，确认未发送或明确拒绝才释放。原请求之后的读取失败不能冒充「未发送」。
- 募兵跨重启记录通过同日完成计数增长确认。确认回执但计数尚未更新时仍不提交下一单；未知记录跨日仍阻止重复消费。
- 自动科技把次数直接加入原单级升级票据，避免界面／自动模式重复占额；费用、等级、前置、阶段或配置变化时不会发送旧计划。

## 接口与验证

`runAllianceAutomation(client, protocol, config, player, { getSettings, ledger, enabled, report })` 执行一轮，`getSettings` 返回完整设置。普通轮次每种消费最多一次；收到首条回赠后的余下求助和 23:40 后帮助补齐会逐条重读再发送。

`readAllianceRecruitDemand(...)` 返回可进入工厂的当前募兵需求；`surveyBaseAutomation` 的可选第七参 `{ledger,enabled}` 用于将未知请求保护和暂停检查传入补产调查。

`tools/selftest-alliance-automation.mjs` 使用临时数据目录、假客户端及真实 protobuf 编解码，覆盖总开关、已有援助领取、大整数 ID、筛选／保留、共享日限、首条回赠握手、未知跨重启、参数变化、午夜补齐、募兵额度与工厂需求、科技升级。现有联盟订单、手动互助和科技测试仍需通过。
